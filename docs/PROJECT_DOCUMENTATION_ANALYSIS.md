# プロジェクトドキュメント構成

このプロジェクトの `docs` ディレクトリは、アプリケーションの概念から設計、日々の開発記録まで、多岐にわたる情報を体系的に整理するために構築されています。各ドキュメントは特定の目的を持ち、プロジェクトに関わる全ての人が必要な情報へ迅速にアクセスできるよう設計されています。

## 1. ドキュメントの全体像

本プロジェクトのドキュメントは、大きく分けて以下の 4 つのカテゴリに分類されます。

1.  **コンセプトと要件 (`01_concept_and_requirements/`)**:
    - プロジェクトが「なぜ」存在するのか、そして「何を」目指しているのかを定義します。
2.  **設計とアーキテクチャ (`02_design_and_architecture/`)**:
    - アプリケーションが「どのように」構築されているか、その技術的な構造とデータの流れを記述します。
3.  **計画と分析 (`03_planning_and_analysis/`)**:
    - 開発プロセスにおける具体的な計画、分析、そして意思決定の記録です。
4.  **ログとレポート (`04_logs_and_reports/`)**:
    - 開発の過程で得られた知見や日々の進捗を記録します。

## 2. 各ドキュメントの役割

### カテゴリ 1: コンセプトと要件

- **`CONCEPT.md`**:
  - **目的**: このアプリケーションが解決しようとしている課題と、それによってもたらされる価値（世界観）をエモーショナルに伝えます。
  - **ターゲット読者**: プロジェクトメンバー全員、特に新規参加者。
- **`DEVELOPMENT_RULES.md`**:
  - **目的**: コーディング規約やコミットメッセージのルールなど、開発を円滑に進めるための基本的なルールを定めます。
  - **ターゲット読者**: 開発者。
- **`REQUIREMENTS.md`**:
  - **目的**: 実装すべき機能（機能要件）と、満たすべき品質（非機能要件）を具体的に定義します。
  - **ターゲット読者**: 開発者、プロジェクトマネージャー。

### カテゴリ 2: 設計とアーキテクチャ

- **`DATA_FLOW.md`**:
  - **目的**: アプリケーション内でのデータの流れを図解し、システム全体の動作を視覚的に理解しやすくします。
  - **ターゲット読者**: 開発者。
- **`technical/` ディレクトリ**:
  - **目的**: API の利用方法や特定の技術課題に関する詳細な技術ドキュメントを格納します。
  - **ターゲット読者**: 開発者。

### カテゴリ 3: 計画と分析

- **`DEMO_CHECKLIST.md`**:
  - **目的**: デモやプレゼンテーションの際に、確認すべき項目や話す内容をリストアップします。
  - **ターゲット読者**: プレゼンテーション担当者。
- **`UI_UX_IMPROVEMENTS.md`**:
  - **目的**: ユーザー体験を向上させるための具体的な改善案やアイデアを記録します。
  - **ターゲット読者**: 開発者、デザイナー。

### カテゴリ 4: ログとレポート

- **`DEVELOPMENT_LOG.md`**:
  - **目的**: 日々の開発作業の記録や、発生した問題とその解決策を時系列で記録します。
  - **ターゲット読者**: 開発者。
- **`ASSISTANT_SELF_ANALYSIS.md`**:
  - **目的**: AI アシスタント（Cline）の自己評価や、開発プロセスへの貢献度を分析・記録します。
  - **ターゲット読者**: プロジェクトマネージャー、AI アシスタントの利用者。

---

この構成により、プロジェクトの情報が一元管理され、透明性とメンテナンス性が向上します。新しいドキュメントを追加する際は、この構造に従うことが推奨されます。
