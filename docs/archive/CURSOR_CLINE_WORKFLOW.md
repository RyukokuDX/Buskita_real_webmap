# Cursor と Cline による効率的な開発ワークフロー

## 概要

本ドキュメントは、Cursor の対話的なコード編集機能と、Cline の計画的なタスク実行能力を組み合わせ、開発を効率化するためのワークフローを提案するものです。

## 基本的な考え方

- **Cline**: プロジェクト全体を俯瞰し、**大規模な変更や複雑なタスクの計画（Plan）と実行（Act）**を担当する「建築家」や「プロジェクトマネージャー」のような役割。
- **Cursor**: Cline が立てた計画に基づき、**具体的なコードの記述や修正**を行う「職人」のような役割。

この役割分担により、トップダウン（Cline）とボトムアップ（Cursor）のアプローチを組み合わせ、手戻りの少ない効率的な開発を実現します。

## ワークフローのステップ

### Step 1: 【Cline: Plan モード】 計画の立案

新しい機能の追加や大規模なリファクタリングなど、影響範囲の広いタスクに着手する際に、まず Cline を**Plan モード**で起動します。

1.  **要件の提示**: 実現したいことを自然言語で Cline に伝えます。
2.  **コードベースの分析**: Cline はプロジェクト全体のファイルを読み込み、関連する箇所を特定・分析します。
3.  **方針の決定**: Cline は複数の実装アプローチを提案します。対話を通じて、最適な方針、影響範囲、具体的な作業手順を明確にします。
4.  **計画の文書化**: （任意）決定した計画をマークダウンファイルとして出力させ、チームで共有することも有効です。

### Step 2: 【Cursor】 具体的な実装

Cline で決定した計画に基づき、Cursor の得意な対話型コーディングで、具体的な実装を進めます。

1.  **コード生成**: Cursor のチャット機能やインライン編集（Ctrl+K など）を使い、必要な関数やクラスの雛形を生成します。
2.  **コード修正・リファクタリング**: 既存のコードを選択し、修正や改善の指示を与えることで、効率的にリファクタリングを行います。
3.  **部分的なテスト**: 細かい単位でコードを記述・修正し、その都度、動作確認を行います。

### Step 3: 【Cline: Act モード】 変更の適用と検証

Cursor で作成・修正したコードを、プロジェクト全体に統合し、検証します。

1.  **計画の実行**: **Act モード**に切り替え、Step 1 で立てた計画を実行させます。
2.  **複数ファイルへの変更適用**: Cline は、計画に基づいて複数のファイルにまたがる変更を一度に適用します。
3.  **ビルドとテスト**: 変更適用後、ビルドコマンドやテストコマンドを実行させ、プロジェクト全体でデグレードが発生していないかを確認します。

### Step 4: イテレーション

開発は常に計画通りに進むとは限りません。実装の途中で問題が発生したり、より良いアプローチに気づいた場合は、柔軟に各ステップを行き来します。

- **計画の修正**: 実装が困難な場合や、仕様の変更が必要になった場合は、再び**Plan モード**に戻り、計画を練り直します。
- **実装の微調整**: テストで問題が見つかった場合は、**Cursor**で迅速にコードを修正します。

この「計画 → 実装 → 適用・検証」のサイクルを繰り返すことで、複雑なタスクを管理しやすくし、開発の質と速度を向上させることができます。
