# Cursor & Cline 開発ガイド

## 1. 概要

このドキュメントは、Cursor の強力なコード編集能力と、Cline の高度な計画・実行能力を組み合わせた、効率的な開発ワークフローの実践ガイドです。役割分担、具体的な指示方法、ユーザーの作業手順を明確にすることで、AI との協調作業を最大化します。

## 2. 役割分担：最適なツールを最適なタスクに

それぞれのツールの長所を理解し、タスクに応じて使い分けることが重要です。

### Cline：プロジェクトの「建築家」「監督」

プロジェクト全体の構造を理解し、大規模で複雑なタスクを計画・実行する役割を担います。

| 得意なこと（ユースケース）                 | 苦手なこと                         |
| :----------------------------------------- | :--------------------------------- |
| **大規模リファクタリングの計画**           | 対話を通じた細かいコードの試行錯誤 |
| **新機能追加の影響範囲分析**               | UI のピクセル単位の微調整          |
| **複数ファイルにまたがる一括変更**         | リアルタイムのデバッグ支援         |
| **プロジェクト全体のコーディング規約適用** | アイデア出しやブレインストーミング |
| **テスト計画の策定と自動実行**             |                                    |

**→ 「この機能を追加したいが、どこをどう変更すれば良いか？」という問いに最適**

### Cursor：コードの「職人」「ペアプログラマー」

特定のファイル内で、具体的かつ高品質なコードを迅速に記述・修正する役割を担います。

| 得意なこと（ユースケース）                   | 苦手なこと                           |
| :------------------------------------------- | :----------------------------------- |
| **特定の関数やクラスの実装**                 | プロジェクト全体の構造を考慮した設計 |
| **アルゴリズムのコード化**                   | 複数ファイル間の依存関係の解決       |
| **既存コードの品質改善（リファクタリング）** | 大規模な変更による影響範囲の予測     |
| **バグの特定と修正**                         | アーキテクチャレベルの意思決定       |
| **ドキュメントやコメントの自動生成**         |                                      |

**→ 「このファイルに、こういう仕様の関数を作って」という指示に最適**

## 3. AI への指示書テンプレート

効果的な指示は、良い成果物を生み出す鍵です。以下の要素を意識してください。

- **`Context`（背景）**: なぜこのタスクが必要なのか？
- **`Objective`（目的）**: 何を達成したいのか？ 具体的な成果物は？
- **`Scope`（範囲）**: 対象となるファイルや機能は？
- **`Constraints`（制約）**: 守るべきルール（言語、バージョン、規約など）は？

### Cline (Plan モード) への指示例

> **[Context]** 現在、ユーザー認証はメールアドレスとパスワードのみです。セキュリティ向上のため、Google アカウントによる OAuth2.0 認証を追加する必要があります。
> **[Objective]** Google OAuth2.0 認証を実装するための、詳細な手順と影響範囲を分析した計画書を作成してください。
> **[Scope]** 認証関連のバックエンド処理（例: `auth.py`, `models.py`）と、フロントエンドのログインページ（例: `login.html`）が対象です。
> **[Constraints]** Flask-Dance ライブラリを使用してください。既存の認証システムとの後方互換性を維持する必要があります。最終的なアウトプットは、変更が必要なファイルリストと、それぞれのファイルに対する具体的な修正指示（diff 形式が望ましい）を含むマークダウンファイルです。

### Cursor への指示例

> （`auth_utils.py` を開いた状態で）
>
> **[Objective]** ここに、Google から受け取った ID トークンを検証する関数 `verify_google_id_token` を作成してください。
> **[Scope]** この関数は、引数として ID トークン（文字列）を受け取ります。
> **[Constraints]** `google-auth`ライブラリを使用してください。検証に成功した場合はユーザー情報を、失敗した場合は `None` を返すように実装してください。適切なエラーハンドリングとドキュメントコメントも付与してください。

## 4. ユーザーの手順書：3 フェーズ・ワークフロー

### フェーズ 1：【計画】Cline と共に全体像を描く

1.  **タスクの定義**: まず、あなた自身が「何をしたいのか」を明確にします。（例：「ユーザープロフィール編集機能を追加する」）
2.  **Cline (Plan モード) の起動**: ターミナルで `cline --plan "（ここにタスク定義）"` のように入力し、対話を開始します。
3.  **対話による計画策定**: 上記の指示書テンプレートを参考に、Cline と対話します。Cline はコードベースを分析し、実装方針、影響範囲、作業リストなどを提案します。
4.  **計画のレビューと確定**: Cline が生成した計画（例: `plan.md`）を確認します。内容に問題がなければ、この計画を実装の設計図として確定します。

### フェーズ 2：【実装】Cursor と共にコードを創造する

1.  **ファイルの準備**: 計画書で指定されたファイルを Cursor で開きます。
2.  **対話的コーディング**: 計画書の指示に基づき、Cursor のチャットやインライン編集（`Ctrl+K`）機能を使って、具体的なコードを記述・修正していきます。一度にすべてを指示するのではなく、「まずこの関数を」「次にこのクラスを」のように、小さな単位で進めるのがコツです。
3.  **単体テストとデバッグ**: 一つの関数やクラスを実装するたびに、それが正しく動作するかをテストします。バグが見つかれば、Cursor のデバッグ支援機能を活用して修正します。

### フェーズ 3：【統合・検証】Cline で最終確認と適用

1.  **Cline (Act モード) の起動**: Cursor での実装が完了したら、ターミナルで `cline --act` を実行します。
2.  **計画の実行**: フェーズ 1 で確定した計画書ファイルを指定し、プロジェクト全体への変更適用を指示します。Cline は計画に基づき、複数ファイルにまたがる変更を自動的に行います。
3.  **統合テストの実施**: Cline に `pytest` や `npm test` などのプロジェクト全体のテストコマンドを実行させ、他の機能に悪影響（デグレード）が出ていないかを確認します。
4.  **最終レビューとコミット**: 全てのテストが成功したら、最終的なコードレビューを行います。問題がなければ、変更内容をバージョン管理システムにコミットして完了です。
